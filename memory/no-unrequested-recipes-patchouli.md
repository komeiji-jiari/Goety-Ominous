做新仆从/新实体时,只交付用户明确要求的东西:注册、属性、模型渲染、lang、配置。**配方(工作台/熔炉/营火/烟熏/`goety:ritual`)和帕秋莉手册条目一律不主动写**,除非用户点名要。

**Why:** 用户对"这个怪怎么获得、手册里怎么写"有自己的设计安排。擅自补配方等于凭空造出一条获得途径(还可能绕过仪式/灵魂能量等平衡设定);擅自写手册会把没定稿的设定固化进游戏内文档。2026-09-20 的鸸鹋仆从就是没要求就写了转化仪式配方 + en/zh 手册条目,被要求删除。

**How to apply:** 交付新实体停在"刷怪蛋能生成 + AI/渲染正常"为止,`data/**/recipes/`、`patchouli_books/` 以及只为它们服务的 tag 都不碰。需要时开口问,别先斩后奏。删这类文件时注意它们多是 untracked,git 恢复不了。

**2026-10-15 追加:文案也算在内——任何用户可见的文字,我都不许自己写。** 当天给手册新根类目「诡厄凶兆」写 description 时,用户说"按联动那款的格式",我自作主张拟了一句新的(「你已经不再满足于只做诡厄巫法的学徒…」),用户回"一字不差照抄"。凡用户给了一个**参照物**(某条已有文案、"照抄"/"同款"),正确做法是**逐字复制那个参照物**,不是"领会精神再创作"。用户没给参照物时,先问,别先写。这条同样适用于类目名、描述、lang 里的说明文字、按钮提示。
