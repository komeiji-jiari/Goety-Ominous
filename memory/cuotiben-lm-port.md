## 招式的三个必查点

- **第 9 条**：原版是 BOSS，`isAlliedTo` 只管同族；**仆从必须覆写**加上「主人/同伴」这层，否则范围招打自己人。
- **第 12 条**：伤害判定写在 `UpdateWithAttack` 的状态分支里，和 goal 是**两个地方**。只注册 goal = **动画照播，一刀打不到**。⚠️ **这个坑踩了两次**（状态 8、状态 31），移植新招式必对照检查。
- **第 10 条**：招式触发概率**不是字段**，是注册 goal 时**匿名子类里写死的**（`random.nextFloat() * 100 < JumpRandom`）。实体类里翻不到，要去**注册现场**看。
- **第 11 条**：渲染器要读的字段，赋值必须在**客户端也会执行到**的路径上（`UpdateWithAttack` 在 `aiStep` 里调、客户端也跑）；只在服务端 tick 里赋值 → 客户端永远读到默认值，动画/特效不出现或恒为 0。

## 第 15 条：「要求最小距离」的招式移植成仆从后永不触发

扑跃剑阵（招 22，≥6 格）、翻滚二连震地（招 12，≥5 格）、掷三叉戟旋转（招 38，≥7 格）几乎从不放。概率/冷却/注册顺序都对。
**根因：那个距离在原版是「玩家造成的」，不是招式自带的。** 原版是 BOSS，玩家边打边跑，空档随时有；成了仆从后跟着主人一路平推贴脸打，**所有近战招要的都是 5~7 格以内**，距离恒在 0~3 格，下限条件恒 `false`。
**以后**：移植带「最小距离」的招式前先问 —— **「这个距离在原版是谁造成的？」** 玩家跑出来的 → 得自己补位移（试过「后跃拉开距离」，踩了新坑见 [[cuotiben-goety-servant-framework]] 第 18 条）。反过来，`canUse()` 里有 `> 某数` 就要警惕它不是为仆从设计的。

## 第 16 条：限伤写在 `actuallyHurt` 里 = 形同虚设

`actuallyHurt` 拿到的 `amount` **已经过完护甲和抗性**。一记 100 点：动态减伤砍成 50 → 护甲变 15 → 才 `min(15,21)` 还是 15，上限根本没碰到。
**「上限」放伤害链最上游**（`hurt()` 开头、护甲之前），「比例减免」放中间，「护甲」放最后。LM 原版 `IAnimatedBoss.hurt()` 就是把 `Math.min(damageCap, amount)` 写在**第一行**。

## 第 21 条：移速 = 基础速 × 导航倍率

`实际速度 = 导航倍率 × MOVEMENT_SPEED`（`MoveControl.java:98`）。LM 原版是「**小基础速 × 大倍率**」`0.1 × 3.0 = 0.30`（3.0 写在 `IMoveGoal(this,false,3.0F)` 注册处）；**乘积一样，所以打架时完全看不出问题** —— 这就是它能藏这么久的原因。问题出在**没经过那个 3.0 的地方**：Goety `FollowOwnerGoal` 的倍率取 `IServant.getFollowSpeed()`（默认 1.0），`WanderGoal` 倍率是注册时我们自己传的 1.0 → 跟随/闲逛都只有 0.30。原版 BOSS **根本没有这两个 goal**，所以偏差在原版永远暴露不出来。

- **两个数照抄，别自作主张合并。** 觉得基础速 0.1「小得不像话」想调大 —— **那正是这个坑的入口**。
- 查法：把「属性值」和「IMoveGoal 倍率」一起抄下来相乘，和同包同类仆从横着比。飓旋/云铸魔像都是覆写 `getFollowSpeed()=3.0` 救回来的。
- 📌 **但圣骑这条路走了一遍又退回来了（2026-09-25）：圣骑和蔓生巨像一样，三档（追击/跟随/闲逛）全 0.30，一个都不覆写、`WanderGoal` 倍率写回 1.0D。** 覆写 `getFollowSpeed()` 是「技术上的可能性」，不是推荐做法。先后试过跟随 0.5→0.9、闲逛 0.5→0.75，**两次实机手感都不对**。
- ⚠️ 真要调，**跟随速度的下限是「明显快过玩家疾跑」，不是「快过玩家走路」**：玩家 MOVEMENT_SPEED 也是 0.1，疾跑 ×1.3 = **0.13**，再扣寻路损耗，只高一点点（0.15）实机就是「跟不上」。目标至少 **0.25 往上**。
- 定心丸：Goety `FollowOwnerGoal` 拉开 **16 格会自动传送**，压低跟随速度不会导致跟丢。
- ⚠️ 仓库里的 `Goety-master`（1.16.5）和 `Goety-3-main`（1.21.1）是**别的 MC 版本，别信**；查 1.20.1 API 用 `javap` 反编译真实依赖 jar。见 [[goety2-src-decompile]]。

## 第 23 条：改了 `entityData` 的默认值 → 读档/生成路径被悄悄接管

`AWAKENED` 原版默认 `false`，为了兜底改成 `true`。它**不进存档**，所以读档时永远是默认值 → 状态 34（躺下）的 goal 闸门开着 → 下一 tick 直接切 35 演苏醒，喂东西被跳过。**不报错、不崩溃，只是行为反了。**
**以后**：动过 `entityData.define(X, 默认值)` 就**必须回头过三条路径**：① `readAdditionalSaveData` ② `finalizeSpawn` ③ 刚 `new` 出来还没初始化那一瞬。哪条依赖「取默认值就是对的」就显式写死一次。

## 第 25 条：语言键前缀 —— 不崩、不报错，只是什么都不显示

约定是 **`message.goetyominous.…`**，代码里写成了 `goetyominous.message.…`，22 个键**全空**。
**为什么危险**：`Component.translatable(key)` 查不到键**不抛异常**；旧键 `legendary_monsters.message.possessed_paladin_*` 在 LM 的 jar 里**依然存在** → 就算整个语言文件都没加、或漏改某处，游戏也不给任何提示。「键写错」和「台词时机没到」在游戏里长得一模一样。
**以后**：代码和语言文件当一次改动一起验，用错题本里的 PowerShell 自查脚本（抓 java 引用键 → 对语言文件 → 打印缺失）。⚠️ 抓键正则需要**两种段序的 alternation**，否则前缀写反的恰恰会被漏掉。⚠️ **脚本报「全部都错」时先怀疑代码，别先怀疑脚本**（当时差点转头去改脚本，拿短串 `"awaken.1"` 试又恰好能命中，更加坐实错觉 —— 要验得拿**整键**验）。同类静默失效家族：语言键前缀、注册名写错、伤害类型 tag（见 [[cuotiben-tooling]] 第 28 条）。

## 第 30 条：别人有公开 API 就别再抄一份

把弹射物叠的「灵魂碎裂」当自己的东西搬了（新建 `SoulEater` + `LmEffects` + `LmEntityUtil`），结果同一次命中挂**两个** `soul_fracture`：`0.8 × 0.8 = 0.64` 而不是 0.8，图标还并排显示两个。
**根因**：把「**这发弹射物独有的**」和「**全模组共用的**」混为一谈。`ModEffects.SOUL_FRACTURE` 是 LM 的**公开 API**。
**以后**：搬一个资源（状态/伤害类型/音效/粒子/属性）之前**先 grep 使用处数量** —— 只有这发弹射物在用 → 可以搬；**别处也在用**（尤其**对方代码里写死的**）→ 直接用对方的。
「去 LM 化」只做**弹射物自己的**东西：飞行基类、伤害类型、数学换算、动画计时器、拖尾粒子。「共用的效果」不在此列。
