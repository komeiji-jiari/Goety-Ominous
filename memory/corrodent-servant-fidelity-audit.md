**✅ 2026-10-08 白天遁地隐身跟随（Goety 侧新增，AC 没有）**：用户口径"在有光的地方开钻就进入 → 不再攻击、遁地跟随主人 → 主人所在位置够暗且距离 ≤8 格才冒头"。实现 = 单个 latched 字段 `lightHide`：上升沿（`!prevDigging && isDigging()`）且 `isInLight()` 且 `surfaceCooldown<=0` 且 `isFollowing()&&!isStaying()&&!isGuardingArea()&&!isCommanded()&&getTrueOwner()!=null` → 置位 + `setTarget(null)`；**覆写 `setTarget`，`lightHide` 期间丢弃非空目标**（否则目标非空会压死 `CorrodentDigFollowOwnerGoal` 的 `getTarget()==null` 门，"遁地跟随"不成立）；`:245` 的 40t 自动冒头加 `!lightHide`;`CorrodentAttackGoal.canUse` 加 `!lightHide`；退出例程紧跟随自动冒头块：主人格亮度 `<= LIGHT_THRESHOLD` 且 `distanceToSqr <= 64`（8 格 = 与 dig-follow 的启动距离对齐，**别用 4**，否则 4~8 格是"既不跟也不出"的死区）**且 `isSurfaceDark()`** → 在墙里 `nudgeUp(0.25F)`、出土则 `setDigging(false)+setPos(+1y)+0.35y+surfaceCooldown=80`（照抄潜行逃生那套）。`lightHide` 在 `!isDigging()||isCommanded()||hasOwnerEmergeRequest()||isStaying()||owner==null` 时清除（都是玩家主动指令，优先级高于隐身状态）。
**`isSurfaceDark()`**（用户追加要求"不到足够暗的地方不会钻出来"）：`lightAt(level, BlockPos.containing(calculateLightAbovePosition())) <= LIGHT_THRESHOLD` —— 复用现成的 `calculateLightAbovePosition()`（从自身格往上扫到第一个 `!isSuffocating` 的格子：自己在空气格时就是自身格，埋在土里时就是地表那一格），**不能只看主人那格**，否则主人在暗处而仆从正上方是露天白天时它会顶着亮光破土。进入门另加 `isInWall() || canDigBlock(below)`（底下方块不可挖时别进这个状态，否则会卡在"亮处站着、冒不出、陆行跟随又被 `isDigging()` 挡住"的死锁里）。**判据必须用主人的位置**：埋进土里后自己那格的 `getMaxLocalRawBrightness` 恒≈0（只算方块光+天光穿透）。
**✅ 2026-10-08 台阶段/坡沿改下潜（用户追加要求，偏离 AC）**：症状"沿地下挖着走，一到地形台阶/坡沿（方块层断开、脚下短暂悬空）就跳出来"。AC 原逻辑里有两处**按 `!isInWall()` 直接出土**：tick 的 40t 自动冒头（`timeDigging > 40 && !isInWall()`，动作 = `setDigging(false)+setPos(+1y)+0.35上抛`）和 `DiggingMoveControl` 的 else 分支（目标格非 `isSafeDig` 时 `+0.3 上弹` + `nav.stop()`，AC 原样 `CorrodentEntity:546`）。改法 = 新增 `DIG_SEEK_DEPTH = 3`、`nudgeDown()`、`digSinkBelow(pos, maxDrop)` / `digRiseAbove(pos, maxRise)`（下/上找第一个 `isSafeDig` 格，找不到或到世界上下边界返回 null；**先下潜后上浮**，阈值都是 3 = 用户口径"3 格以内还值得下潜/上浮，超过就照旧冒头"）：(a) 40t 自动冒头处，若 `!nav.isDone() && !nav.isStuck()`（正在往挖掘目的地走）：3 格内有可下层 → `nudgeDown(0.25)`；否则 3 格内有可上层 → `nudgeUp(0.25)`；都没有才照旧冒头（保留"卡住/无事可做就出土"的兜底，否则会永久埋着）；(b) `DiggingMoveControl` 非 safe-dig 分支，能把 `wantedX/Y/Z` 改指到 seek 到的格子就继续走，找不到才走原来的 `+0.3` 上弹 + `nav.stop()`；(c) lightHide 冒头分支加 `!onGround() && digSinkBelow != null → nudgeDown`（悬在台阶空隙里先下潜，别在落差中间破土；这一处**只下潜不上浮**——它本来就是"该不该出土"的判据）。
**✅ 2026-10-08 惧光恐慌满 3 秒自动遁地（用户要求"恐慌一段时间后遁地"，先定 5 秒、同日用户改口径要 **3 秒** ⇒ `PANIC_DIG_TIME` = **60**，别按 100 或"5 秒"改回去）**：`CorrodentFearLightGoal` 加 `panicTime`（`start()` 清零 = 每次恐慌重新计时，`tick()` 每 tick ++），满 `PANIC_DIG_TIME`(60) → 清退避 strafe、`nav.stop()`、置 `panicHide = true` 并 `setDigging(true)` 后 return（这一 tick 不再采样退避点/后退）。`panicHide` 是照 `lightHide` 造的第二个 latched 字段：40t 自动冒头门加 `!panicHide`，清除条件 `!isDigging() || isCommanded() || isOwnerSneaking() || isStaying()`，出土例程 = **`panicHide && !lightHide && isSurfaceDark()`**（`!lightHide` 是关键——跟随中已由 lightHide 接管，别让 panicHide 一遇到暗柱子就提前破土）→ 在墙里 `nudgeUp`，否则潜行逃生那套冒头 + `surfaceCooldown = 80`。于是"光还在就埋着，光没了（上方那格变暗）才出来"。
关键时序：panic 钻地后惧光 goal 的 `canUse` 因 `isDigging()` 转 false → `stop()` 会 `setAfraid(false)`，**必须在同 tick 之后才判 lightHide/dig-follow**——`CorrodentDigFollowOwnerGoal.canUse` 有 `!isAfraid()` 门，afraid 没清掉的话"遁地跟随"根本不会启动（照 `CorrodentDigRandomlyGoal` 已被删，别去找它）。
**✅ 2026-10-08 修"遁地状态下过不了一格高的坡" + "恐慌五秒遁地进地面一半立刻回到恐惧状态"（两处都是实测报的，改动理由留档）**：
- **爬不上去的根因是下压力，不是碰撞**。挖掘时只有 `isInWall()`（眼睛没入方块）才 `setNoGravity(true)`；`timeDigging > 40 && !isInWall()` 那一块无条件优先 `digSinkBelow` → `nudgeDown(0.25)`（clamp −0.5），于是"贴地表挖掘/眼睛刚露出地面"的每一 tick 都被 0.08 重力 + 0.25 下压按回原地，`DiggingMoveControl` 稳态约 0.19/tick 的上行冲量永远赢不了 → 1 格台阶上不去。修法 = 判"移动意图向上"时不下潜、改 `nudgeUp(0.25)`，且**不冒头**。**判据必须用 `this.getMoveControl().getWantedY() > this.getY() + 0.5`，不能读 `getNavigation().getPath()` 的下一节点 y**：挖掘导航节点在自身格是 safe dig 时"全部 WALKABLE"，路径直奔目标实体所在的空气格，`遁地跟随` 时下一节点恒比自身高 → 会误判成 wantsUp 把它顶出地面。`wantedY` 是 `DiggingMoveControl` 用 `digSinkBelow/digRiseAbove` 重定向后的**安全挖掘层 y**，正是真实移动意图（平地/跟随时 == 自身 y，前方高一层台阶时 == 高那层）。
- **恐慌钻不进去的根因是脚下方块不可挖**（`#wither_immune`/玻璃/水/不遮挡方块；`lightHide` 入口本来就有 `isInWall() || canDigBlock(below)` 这道门，恐慌路径漏了）。此时挖掘导航器全 BLOCKED（`evaluateBlockPathType` 按 mob 自身格判，自身格是空气 → 无路径 → `traveling` false）→ `timeDigging > 40` 冒头 → 仍在亮处 → 惧光 goal 重开 → 死循环。四处改动：(a) 惧光 goal 恐慌分支 + `stop()` 的 `setDigging(true)` 都补 `canDigBlock(below)` 门（挖不了就继续恐慌/后退，不白钻）；(b) `panicHide && !lightHide && !isSurfaceDark()` 且不在墙里时主动 `nudgeDown(0.25)`（仅当 3 格内有安全挖掘层），真埋进去而不是靠 0.08 重力慢慢沉；(c) `CorrodentAttackGoal.canUse` 加 `!panicHide`（照 `!lightHide` 先例）——否则 `fleeLightFor` 50t 衰减完后攻击 goal 会 `setDigging(false)` 把它从洞里拽出来；(d) 惧光 goal `start()` 只在 `fleeLightFor <= 0` 时清零 `panicTime`——它后退方向就是往暗处走，亮度在阈值附近抖动会让恐慌计时反复归零（计时值现为 60t = 3 秒）。
- 同时删掉 `CorrodentFearLightGoal` 里 AC 继承的 `tryDigTime`/`tryDigPos` 钻地路径（AC 原版是"地面 20t 没挪动就钻"，会与 `panicHide` 脱钩造成 40t 冒头循环）；现在只有 `PANIC_DIG_TIME`(60t) 计时到才钻，且与 `panicHide = true` 同语句置位。

**✅ 2026-10-08 修"越过坡的遁地姿态抽动" + "阳光下遁地时集体蹦出来"（用户实测报的）**：
- **抽动是自己上一版修爬坡时引入的**。上一版判据 `getWantedY() > getY() + 0.5` → `nudgeUp(0.25)`，一旦这个不等式转假立刻回到 `digSinkBelow` → `nudgeDown(0.25)`，两个 0.25 每 tick 互相抵消 ⇒ (a) 位置一顿一顿；(b) 每 tick 净位移掉到 `Mob.isMoving()` 的 0.1 阈值以下 ⇒ `tick()` 顶部那句 `if (!isDigging() || !isMoving()) setDigPitch(approach(0, 10))` 把俯仰角反复按回 0 ⇒ **模型抖**。改为死区规则：`traveling && getY() < layerY - 0.5` → 上顶；`!traveling || getY() > layerY + 0.5` → 下潜（3 格内没有可挖层、且不在移动时才上浮，都没有才冒头）；±0.5 内什么都不做。死区安全，因为这块本身带 `!isInWall()` 门，重力沉降的抖动进不来；`!traveling` 分支与旧语义逐条等价（先下潜→再上浮→否则冒头）。
- **集体蹦出来 = 出土判据用了 7**。`isSurfaceDark()` 与 lightHide 出土处的 `lightAt(owner)` 原本都用 `LIGHT_THRESHOLD`(7) = **和怕光触发同一个阈值** ⇒ 太阳一暗（晴天 `Level.updateSkyBrightness()`：`skyDarken ≥ 8` ⇒ dayTime ≈ 12430，18:40 左右，**画面上还是黄昏太阳**）就全体同时满足 `isSurfaceDark()` → 同一 tick 一起破土。修法 = 新常量 `EMERGE_LIGHT_THRESHOLD = 4`，**只给"该不该出土"用**（`isSurfaceDark()` + 主人格亮度），7 仍管怕光触发/lightHide 入口/寻路禁行。数值边界：`skyDarken` 上限 11 ⇒ **露天午夜正好 15−11 = 4**，所以只能是 4、不能更低（3 就变成露天夜里永远不出来）；被遮挡格天空光 0 ⇒ 洞穴/屋檐下照旧能出；火把照亮的洞仍算"亮" ⇒ 继续埋着（怕光意图不变）。雨天不算触发源：满雨 + 满雷正午 `skyDarken` 才 5（光 10）。**若用户下次仍嫌"在有屋檐的地方过早集体冒头"，那是"盖住就出土"这条有意行为，不是这里的阈值，得另想（比如错开/只在主人离开露天时冒）。**

**✅ 2026-10-08 修"出土时后半截抽动"（有意偏离 AC，新加 `fakeDigPitch`）**：根因不是 `isMoving()`（那是上一条的死区问题），而是 **±90 瞬时写入经 5 刻延迟线放大**。模型里 `hipsPivot` 是 `chest` 的子节点，`ModelCorrodentServant:258/261` = `chest.rotateAngleX += digPitch`（当前值）+ `hipsPivot.rotateAngleX += trail(5,0) − digPitch` ⇒ **后半截的绝对俯仰 = 5 刻前的 digPitch**。而 `tick()` 的 `setDigPitch(90.0F)`（入土，:252）与 `setDigPitch(-90.0F)`（出土，:340）是**一步到位**写进 `DIG_PITCH` 的：出土那刻 0 → −90 一拍完成，前身（chest）当场立起来，5 刻后延迟线把这 90° 台阶原样喂给后半截 → 后半截在"前身已经回落到 −50 左右"时**单拍抽 90°**，就是用户报的抽动。AC 原版同样喂原始值，所以这是 AC 侧固有瑕疵，不是移植漏抄。
