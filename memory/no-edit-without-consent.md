**2026-10-29 用户原话：「edit 以后也给你权限」。** 这是对旧规则的**明确推翻**：此前「必须字面出现 edit 才能改文件」的限制**不再适用**，本项目默认允许使用 Write/Edit 修改代码。

**仍然保留的习惯（用户此前多次强调，未撤销）：**
- 只改用户当前要求的那部分；不顺手重构、不顺手加注释、不顺手删"看着像死代码"的东西。
- 不被要求就不建多余文件；新建资源/json 后记得 `git add`（见 [[git-add-new-files]]）。
- 用户说构建才构建（见 [[no-auto-build-jar]]）。
- 提交/推送仍要用户明说。

**Why:** 用户此前被"擅自创建文件/擅自改代码"坑过多次（2026-09-15 MiredServant 建 4 个文件被要求删除；2026-09-27 Abyss 法术加强；2026-10-05 mace mixin）。2026-10-29 主动放宽为长期授权，但仍然在意"改动范围失控"，而非"是否允许 edit"。

**How to apply:** 拿起 Edit/Write 前不再等 "edit" 这个词；但仍先确认改的是不是用户问的那几行。大改（新建文件、跨多文件重构）依旧先给方案/行号，等用户点头。
