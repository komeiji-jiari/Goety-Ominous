**2026-09-30 起本机 Avast 已彻底卸载**（见 [[windows-debloat-avast-xbox]]），原先记录的 MITM 根因不复存在。当时为绕过它加的 `-Djavax.net.ssl.trustStoreType=Windows-ROOT` 已无必要——仓库 `D:\ark\java` 内确认没有这个字符串，要清就查 IntelliJ 运行配置和环境变量。

**Why:** 保留排查法本身仍然有用——Java 报 `PKIX path building failed: unable to find valid certification path to requested target` 的经典根因是**有东西在重签 TLS**（杀软 HTTPS 扫描、企业代理），不是墙、不是 DNS 污染、也不是 jar 损坏。

**How to apply:** 两步确诊：`openssl s_client -connect <host>:443 -servername <host>` 的证书链在 depth 0 就断（上溯不到可信根），且 `Cert:\LocalMachine\Root` 里存在对应的自签根（当年是 `CN=Avast Web/Mail Shield Root`，`OU=generated by Avast Antivirus for SSL/TLS scanning`）。坐实后加 `-Djavax.net.ssl.trustStoreType=Windows-ROOT`（Java 9+ 支持）。相关：[[java-toolchain-location]]、[[forge-compile-setup]]。
